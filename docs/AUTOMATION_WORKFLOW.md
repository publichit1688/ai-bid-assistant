# 自动开发主指令与工作流

## 长期复用主指令

以下内容可直接作为后续会话的开场指令：

> 接管当前 AI 标书助手项目，严格先读取 AGENTS.md、docs/PROJECT_STATE.md、docs/ROADMAP.md、docs/ACTIVE_TASK.md 和 TASKS.md，并检查 git status 与相关代码。按 TASKS.md 从高到低选择第一个未完成且无阻塞的小任务；本次只完成一个可验证批次，不扩展 Dashboard，不进行无关重构。必须保护 PDF 响应式、风险高亮、Dashboard 预警穿透、项目中心、风险检查器、项目对比、报告导出和 AI 缓存。修改后运行相关 lint/build/编译/启动/接口或回归测试，失败先修复，不带错误进入下一任务。不得输出或提交 API Key，不删除数据库、上传文件和报告，不执行危险 Git 操作。完成后更新 docs/PROJECT_STATE.md、docs/ACTIVE_TASK.md、TASKS.md、CHANGELOG.md，并用中文报告本次完成、修改文件、测试结果、当前进度和下一步。

日常可简化为一句：

> 继续自动开发。

`AGENTS.md` 已定义这句话的执行含义。

## 固定工作流

1. **读取状态**：读取五个治理文件，检查 Git 工作区和目标代码。
2. **选择批次**：只取最高优先级的一个最小任务，写清验收条件。
3. **保护回归**：列出本次可能影响的既有功能和数据。
4. **实施修改**：小步编辑，不顺带新增功能或清理用户数据。
5. **自动验证**：执行相关静态检查、构建、编译、启动、接口和最小人工回归。
6. **失败闭环**：先定位并修复；若受外部条件阻塞，记录命令、错误和所需条件。
7. **同步状态**：更新项目状态、当前任务、任务勾选和变更日志。
8. **停止报告**：一个批次结束后停止，等待下一次“继续自动开发”。

## 任务完成判定

“代码已写”不等于“任务完成”。只有实现、验证、回归和文档同步均完成，任务才可从 `[ ]` 改为 `[x]`。真实 Key、部署账号、真实标书授权等外部条件缺失时，不伪造验证结果。
