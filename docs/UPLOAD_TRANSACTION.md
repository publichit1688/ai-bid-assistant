# 上传文件与数据库事务规则

更新时间：2026-08-29

## 成功流程

1. 保留经过基础文件名提取的原始名称，用于项目中心显示。
2. 在 `uploads/` 创建仅属于本请求的 UUID 临时文件。
3. 使用临时文件完成文档解析、AI 分析和风险评分。
4. 全部分析成功后，将临时文件原子移动到 UUID 唯一正式文件名。
5. 数据库记录保存原始显示名称和唯一正式文件路径。
6. 数据库提交成功后，该正式文件才允许长期保留。

相同原始文件名可以多次上传，每次生成不同存储路径，不覆盖旧文件。

## 失败清理规则

- 文件复制、文档解析、AI 调用、响应校验、文件提升或数据库提交任一步失败，都执行数据库回滚。
- 失败时只清理当前请求生成的 UUID 临时路径和正式路径，不扫描或删除 `uploads/` 中的其他文件。
- 清理函数会确认目标文件的父目录正是当前 `uploads/`，拒绝删除目录外路径。
- 已成功提交的文件和数据库记录不会进入失败清理流程。
- 对外返回安全的结构化错误，不返回本机路径和原始异常文本。
