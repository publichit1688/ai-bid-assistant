# 风险数据与评分契约

更新时间：2026-08-29

本契约由 `backend/app/services/risk_scoring.py` 实现，上传响应、项目列表、项目详情、Dashboard 和项目对比使用同一组汇总字段。

## 输入兼容规则

- 风险集合不是列表时按空列表处理。
- 列表内只有字典对象属于有效风险；损坏的字符串、数字和空值被忽略。
- `level` 允许为空或自由文本，按“高 → 中 → 低 → 未知”的优先级归入唯一等级。
- 因此“中低风险”只归入中风险，不会同时增加中、低两个计数。
- 未知等级计入 `risk_count`，但不增加 `high_count`、`middle_count` 或 `low_count`。

## 扣分规则

- 已保存 `deduction` 时优先使用；可转换为整数的字符串兼容旧数据。
- 已保存扣分统一限制在 0–25，负数按 0、超过 25 按 25、损坏值按 0 处理。
- 缺少 `deduction` 的旧数据按等级补算：高 20、中 8、低 3、未知 5。
- 旧数据的关键词或原因包含致命风险词时额外扣 5，单项仍不超过 25。
- 总分为 `max(100 - total_deduction, 0)`。

## 输出字段

- `score`：0–100 的整数评分。
- `score_level`：85–100 低风险、70–84 中低风险、60–69 中风险、40–59 高风险、0–39 极高风险。
- `risk_count`：有效风险对象总数。
- `high_count`、`middle_count`、`low_count`：互斥等级计数。
- `total_deduction`：所有有效风险的规范化扣分总和。

修改本契约时必须同步更新 `backend/tests/test_risk_scoring.py`，并验证项目列表、详情和 Dashboard 的跨接口一致性测试。
