# P2 合并单元格表格回归审计

日期：2026-09-02

本记录仅包含脱敏编号和统计。原件、完整模型输出、报告和本地审计 JSON 均位于隔离目录或 Git 忽略目录，不进入版本库。

## 样本范围

- 脱敏编号：`RB-PDF-TABLE`
- PDF页数：4页
- 可检测表格：1个
- 表格特征：跨行合并单元格、多个采购项、规格/要求、预算、数量及进口产品列
- 边界：属于中等复杂度合并单元格表格，不代表多页密集、嵌套或大量跨页表格

## 首次执行发现

首次真实 DeepSeek 分析返回 HTTP 200，但分析结果没有命中13个非空表格单元格中的任何一个。风险定位和报告正常，但“表格字段进入分析”未通过，因此没有标记成功。

## 修复

- 提示词要求逐页检查表格、清单和合并单元格。
- 新增结构化 `procurement_requirements`：标的、规格/要求、数量、预算、进口产品和真实页码。
- 没有明确值时必须留空，不允许模型编造。
- 前端分析卡增加采购清单展示；Word 报告增加采购清单摘要。
- 增加提示词契约与报告字段自动化测试。

## 修复后复验

- 上传分析接口：HTTP 200
- 评分：0分
- 风险：6项
- 风险页码有效：6/6
- 引用逐字命中：6/6
- 高亮连续命中：6/6
- 结构化采购项：4项
- 非空采购字段：20个
- 字段可在源PDF中找到：20/20
- 采购项页码有效：4/4
- 每个采购项至少一个字段在其指定页命中：4/4
- 报告可重开，项目名称、评分、风险数、总扣分和采购项全部一致

## 结论

该中等复杂度合并单元格样本的解析、结构化采购字段、风险定位、前端数据契约和报告导出通过。更复杂的跨页/嵌套表格仍作为后续扩展覆盖，不在本次结论内。
