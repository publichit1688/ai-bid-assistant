# 产品与工程路线图

路线严格按阶段推进；前一阶段未达到退出条件，不进入后一阶段。

## P0：V1 UI 全局收尾

目标：不增加 Dashboard 业务模块，统一已有页面体验。

- 清理 Vite 示例全局样式，建立统一 Content 背景、页面间距、标题层级和卡片边界。
- 将文本 emoji 逐步替换为一致的 Ant Design 图标，保留语义和可访问提示。
- 统一加载、错误、空状态与无数据提示。
- 检查窄屏和不同侧栏折叠组合下的响应式布局。
- 回归 PDF 响应式、风险高亮、Dashboard 穿透、项目中心、风险检查器、项目对比和报告导出。

退出条件：前端 lint/build 通过；核心交互回归通过；无新增 Dashboard 功能。

## P1：稳定性与数据一致性

- 统一前后端字段默认值、风险等级、评分和时间语义。
- 为上传、解析、AI JSON、数据库事务、缓存和报告生成补充明确错误处理。
- 建立后端最小自动测试和前端关键纯逻辑测试。
- 处理并发上传、重复请求、缓存失效和损坏历史数据的降级路径。

退出条件：核心接口测试通过；失败状态不产生半成品数据；同一数据在 Dashboard、项目详情和对比页语义一致。

## P2：真实标书回归测试

- 使用已获授权且脱敏的 PDF/DOCX 样本覆盖短文档、长文档、扫描件、复杂表格和异常文件。
- 建立固定预期：项目信息、评分、风险页码、关键词高亮、缓存命中和报告内容。
- 记录失败样本，不把真实标书和个人信息提交到 Git。

退出条件：回归清单完成并留存脱敏结果；关键失败有明确处置或已知限制。

## P3：部署与安全

- 容器化或标准化进程启动，配置健康检查、持久化卷、反向代理和日志轮转。
- 环境变量驱动数据库位置、上传/报告目录、CORS、模型和请求限制。
- 增加文件类型/大小校验、路径安全、超时、速率限制、鉴权和备份恢复方案。
- 完成依赖漏洞、秘密扫描和最小权限检查。

退出条件：在类生产环境可重复部署；密钥不落日志/仓库；备份恢复和健康检查可验证。

## P4：V1 功能冻结

- 只接受阻塞缺陷、安全缺陷和明确的数据一致性修复。
- 固化版本号、发布说明、回归结果和已知限制。
- 建立 V1 分支/标签策略，但未经用户授权不执行发布或危险 Git 操作。

退出条件：发布清单签署，V1.0.0 可部署、可回滚、可说明。

## P5：V1.5 智能编标工作台（当前）

- 从招标文件生成可编辑的投标文件目录建议。
- 提取评分点，并映射到目录章节、响应材料和责任人状态。
- 保留人工确认、来源引用、版本记录和缺口提示。
- 明确不做：一键生成整本投标文件、无来源的内容补写、自动提交投标。

退出条件：目录生成和评分点映射形成可审计的最小闭环。

## P6：V1.5正式版后维护

- 只处理已知弃用、性能、稳定性和安全问题，不移动既有 `v1.5.0` 标签。
- 优先消除明确控制台弃用提醒，再审计页面级拆包边界。
- 每项维护改动继续保持小批验证；需要发布时另行进入补丁版本流程。
- 真实部署门禁发现的备份原子性缺陷以 `1.5.2-rc.1` 独立维护候选处理，不移动已发布 `v1.5.1` 标签。
- `1.5.2-rc.1` 已完成腾讯云隔离候选门禁并经授权提升为本地正式 `1.5.2`；标签、推送和部署仍需分别明确授权。

退出条件：已知前端弃用项有明确处置，拆包方案不破坏PDF预览、风险检查器、Dashboard、项目对比和智能编标工作台。
